# Agent 主机监控与资源邮件告警

本功能用于 1～20 台 Linux Agent 主机的人工选机，不改变任务调度、同时执行、轮询、启停或任务权限。非 Agent 节点和本机执行不纳入资源采集。

## 使用入口与指标口径

在任务新增、编辑、复制页及执行资源列表点击 **查看主机负载 / 告警**。面板支持按任务数、CPU、可用内存和负载/核数排序；确认后将勾选同步回原服务器选择器。刷新不会修改表单或已选节点。

- **已分配 / 已启用**：全平台绑定该服务器的任务数量；已分配包含状态 0、1、2、3，排除删除任务。重复节点去重，轮询任务在每个绑定节点各计一次。数量不是正在执行数，也不代表资源消耗。
- **CPU**：相邻成功采样的累计 CPU 时间差，排除 idle 和 iowait，guest 不重复计入总量。首次采样、主机重启、采样间隔超过 90 秒时先显示未知。
- **内存**：`(MemTotal - MemAvailable) / MemTotal`，不是 Go 进程内存。
- **负载 / 核数**：一分钟 load average 除以逻辑 CPU 数，不是 CPU 百分比；Agent 同时返回 5/15 分钟负载。
- **磁盘**：仅代表 Agent `MonitorDiskPath` 所在文件系统，默认 `/`。爬虫数据写在独立数据盘时应改成实际目录，例如 `/data`。
- 每 60 秒采样，最多 5 台并发，单次连接及 RPC 总超时 5 秒。数据超过 180 秒未更新标记过期；采集失败不是主机宕机证明。
- 历史只查询最近 72 小时，每小时分批清理旧记录。支持近 1 小时、24 小时、3 天，缺失数据不补零、不连接曲线。每台最多返回 4,320 个分钟采样点。

用户只可读取已授权服务器分组的指标；可以看到该主机的全平台任务汇总数，但不会得到无权限任务名称、命令和详情。超级管理员（现有 ID 1）管理全局规则与单机开关。

## 告警规则与投递

全局告警默认关闭；单机开关默认开启。超级管理员通过面板的 **告警配置** 设置规则及启用用户的邮箱：

| 类型 | 初始触发条件 |
|---|---|
| CPU | 使用率 ≥ 90%，连续 300 秒 |
| 内存 | 使用率 ≥ 90%，连续 180 秒 |
| 磁盘 | 可用比例 < 10%，连续 180 秒 |
| 采集异常 | 曾成功接入监控的 Agent 连续 3 次采集失败 |

持续时间按采样时间戳计算：每分钟一次的五个连续采样仅跨越四分钟。未知指标会中断待触发计时，不会恢复活动告警。各类型均在连续两次有效正常采样后恢复；CPU 首次计算中的空值不算正常。

每个异常只创建首次、恢复两个通知事件，每位收件人独立记录，不周期性重复提醒。状态和投递记录持久保存，主控重启不会重建活动事件；停机空白不算持续超限。关闭全局或单机告警会取消待发通知并结束状态，不发送假恢复通知。

邮件复用 `conf/app.conf` 的 `email.host/port/user/password/from`，支持原有 25（可用时 STARTTLS）和 465（TLS）端口，连接/协议总超时 10 秒。投递失败按 1、5、15 分钟最多重试三次，最终失败在告警记录中显示。**已提交 SMTP 不表示收件箱送达或已读**；SMTP 接受后、状态落库前发生崩溃时仍可能重复投递。

恢复会取消尚未开始发送的过期首次邮件；仅对已经成功提交首次邮件的收件人发送恢复邮件。发送过程中恢复的，首次发送成功后再排队恢复邮件，保证顺序。正常结束的记录保留三天，未恢复状态不随指标清理。

收件人和 SMTP 连通性必须在部署环境确认后再开启全局开关。本次自动化测试只使用伪 SMTP 和投递替身，不发送真实邮件。PPGo 自身停机需要独立监控，本模块不能自行报告其宿主进程停机。

## 升级与回退

1. 备份数据库。先执行现有的 `migrations/20261109_task_search.sql`（此前已升级搜索则无需补做），再执行 `migrations/20261110_server_monitor.sql`。
2. 若表前缀不是 `pp_`，在执行迁移的**同一连接**先设置 `SET @ppgo_prefix='实际前缀';`。迁移可重复执行，只新增监控表及服务器告警开关；不要重新导入旧初始化 SQL。
3. 使用 Go 1.22+ 构建主控与 Agent，例如在 Linux 上执行：

   ```sh
   go build -o ppgo-job-custom .
   go build -o ppgo-agent-custom ./agent
   ```

4. 停止旧主控后替换程序、`views`、`static`，保留原配置和密钥。不并行运行两套调度器。
5. 全局告警保持关闭，在空闲时先升级一台 Agent，保留原 Agent 配置；需要时添加 `MonitorDiskPath=/data`。确认 CPU 在两次采样后出现、内存和磁盘路径正确，再逐台升级。
6. 验证真实收件人和 SMTP 后显式开启告警。Agent 沿用原端口，网络访问限制为主控。旧 Agent 的任务 RPC 和心跳不变，未升级节点显示不支持监控，不会自动被停用。

新增监控表或数据库访问异常会记录错误；不要跳过迁移直接替换程序，服务器模型新增的列必须先存在。回退时停止新版，恢复旧二进制和页面，保留新增表/列即可。

已修复阻止 Linux Agent 构建的点导入 `RpcResult` 冲突。原 Agent 的 Windows 信号处理仍不支持 Windows，未扩展平台范围。

## 接口

均要求有效登录，并在后端按服务器分组检查权限：

- `GET /server/monitor`：最新快照、是否超级管理员。
- `GET /server/monitorhistory?server_id=ID&range=1h|24h|72h`：单机分钟历史。
- `GET /server/monitoralerts`：活动告警及最近 200 条通知记录，不返回收件邮箱、任务命令或凭据。
- `GET/POST /server/monitorsettings`：超级管理员读取/保存全局配置。
- `POST /server/monitoralert`：超级管理员保存 `{ "server_id": 1, "enabled": false }`。

写接口使用 JSON、`X-PPGo-Monitor: 1` 请求头及同源校验，反向代理应保留原始 Host。修改配置不会直接执行任务或发送测试邮件。

## 针对性验证

数据库集成测试仅接受本机 TCP、以 `_test` 结尾的专用库，通过 `PPGO_TEST_MYSQL_DSN` 显式配置。测试使用唯一表前缀并清理自己的表，不使用应用数据库配置。未设置时数据库测试会明确 SKIP，不能算数据库验证通过。

```sh
go test ./internal/hostmetrics ./notify ./monitor -count=1
go test ./controllers -run '^TestMonitorHTTPAuthorization$' -count=1
go test ./controllers -run '^Test(ParseTaskSearch|TaskSearchHTTPIntegration)$' -count=1
node --test tests/server-monitor-ui.test.cjs tests/task-search-ui.test.cjs
```

两个控制器集成测试分别运行，避免旧测试辅助程序在同一进程重复注册默认 ORM。`node tests/server-monitor-browser.cjs` 提供本机 18081 端口的隔离 UI 假数据环境，不启动调度器、数据库或邮件发送。
